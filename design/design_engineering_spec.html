03

Add-user flow

optimistic, top-of-feed
FAB tap opens the modal bottom sheet (phone) or switches the action panel to the form (tablet). Fields reset; defaults pre-selected.
On valid submit, button enters loading and the whole form locks (no double-submit). POST /users fires.
Success: sheet dismisses, the returned user is prepended to the feed, count increments, the new row gets a brief amber highlight, and a “{name} added” snackbar confirms (~3s, non-blocking).
Error: sheet stays open, all input preserved, inline error banner inside the sheet, button → “Try again”. Field-level 422s attach to their field instead.
Offline: queue the create locally, insert an optimistic row tagged pending-sync, and reconcile on reconnect. (Flagged — confirm whether queue-offline is in scope for v1.)
Ordering: the feed sorts newest-first by “last active”; a just-created user is treated as just now, so it naturally lands at the top. Don’t hard-pin — let the sort do it.
04

Delete & undo

optimistic with a commit timer
Long-press a row (~450ms): row depresses + ripple + one haptic tick, then the AlertDialog confirms. (First run shows a one-time hint: “Hold a user to manage”.)
Confirm: row is removed from the list immediately (collapse animation) but kept in memory with its original index. A snackbar with Undo appears, countdown bar = the window.
Undo (within 5s): re-insert the cached row at its original index, brief highlight, dismiss snackbar. No API call is ever made.
Window expires (or another delete starts): commit — fire DELETE /users/{id}. Success is silent (already gone from UI).
Delete fails at commit: re-insert the row at its index and show an error snackbar “Couldn’t delete — {name} restored” with Retry.

Edge rules

  • Rapid deletes: committing the previous delete immediately if a new one starts (single in-flight undo) keeps it simple; or stack snackbars — pick one and document. Recommend commit-on-next.
  • Leaving the screen with a pending undo → commit the delete.
  • Offline delete: remove locally, queue the DELETE, reconcile on reconnect.

Why optimistic

  • The list feels instant; the network call is deferred to the moment undo is no longer possible.
  • Undo is a pure local operation → always fast, works offline.
  • Failure is recoverable and visible, never a silent data loss.
05

Offline & caching

graceful, never blank

Cache the last successful GET /users response locally (e.g. SQLDelight or a serialized store) together with a fetchedAt timestamp. The feed reads cache-first, then refreshes from network when online.

  • Cache-first render: show cached rows instantly, kick off a background refresh, swap in fresh data on success.
  • Offline + cache: persistent neutral banner “Offline — showing cached users” + fetchedAt as relative “updated N ago”. Feed stays interactive; mutations queue.
  • Offline + no cache: the dedicated no-cache state — honest, with Try again.
  • Connectivity: observe platform connectivity; on regain, auto-refresh and drain the mutation queue.
  • “updated N ago” derives from fetchedAt, not per-row — it’s the sync time, distinct from each user’s “last active”.
Don’t conflate the two timestamps. Banner “updated 12 min ago” = when the feed last synced. Row “5 min ago” = that user’s last-active. They answer different questions.

Options, in order of preference: (a) if you control/seed the backend, add an updated_at field; (b) store a local firstSeen/lastSeen per id as the device observes them; (c) for the demo, derive a stable pseudo-time from the id. Decide before build — it affects the data layer. The UI treatment is identical regardless of source.

09

Accessibility

non-negotiable

Perception

  • Colour never alone: status = chip + label; validity = icon + border + helper text.
  • Contrast pairs in the tokens sheet meet WCAG AA in both themes (verify ink-2 on surface).
  • Honour system Dark Mode and Reduce Motion (see motion table).
  • Respect dynamic type — rows wrap/truncate gracefully (see Hi-Fi edge cases).

Interaction

  • Touch targets ≥ 48dp; row is one large target.
  • Long-press needs an alternative for a11y: expose Delete via the row’s accessibility actions (and the visible button on tablet).
  • Snackbar Undo must be reachable — give the undo window enough time and announce via liveRegion.
  • Content descriptions on FAB (“Add user”), avatar, refresh, and the ✕ / chevrons.
  • Focus moves into the sheet/dialog on open and restores on close.

  • Gender “Other” — keep in UI (and map) or drop to match the API’s male/female?
  • Offline mutations — is queue-and-reconcile in v1, or is offline read-only?
  • Rapid deletes — commit-on-next (recommended) vs. stacked undo snackbars?
  • Edit user — the tablet panel shows an Edit affordance; in scope, or remove for now?
